# 教程 6：DWS 每日行为汇总

## 目标

把 DWD 的事件级明细加工成每天一行的可复用汇总表。10K 样本共有 9 个有效业务日期，因此 DWS 最终应有 9 行。

数据流如下：

```text
ODS 原始数据 10000 行
  -> DWD 有效明细 9997 行 + 异常隔离 3 行
  -> DWS 每日汇总 9 行
```

## 指标定义

| 字段 | 定义 |
|---|---|
| event_count | 当天所有有效行为事件数 |
| active_users | 当天发生任意行为的去重用户数 |
| active_items | 当天被交互的去重商品数 |
| active_categories | 当天被交互的去重类目数 |
| pv_count | 当天浏览事件数 |
| fav_count | 当天收藏事件数 |
| cart_count | 当天加购事件数 |
| buy_count | 当天购买事件数 |
| buyer_users | 当天发生购买的去重用户数 |

`buy_count` 是购买事件数，`buyer_users` 是购买用户数，两者不能混用。一个用户一天购买多次时，前者会增加多次，后者只增加一次。

## 为什么 DWS 不直接保存转化率

转化率可能有多种口径，例如购买事件数除以浏览事件数、购买用户数除以活跃用户数。DWS 先保存稳定的基础分子和分母，ADS 再按具体看板口径计算比例，减少口径变化时重复加工底层数据。

## 分区与幂等性

表按 `dt` 分区，使用 `INSERT OVERWRITE` 重建每日汇总。重复执行同一份固定样本不会累加重复行。

## 执行顺序

1. 上传 `20_build_dws_daily_10k.sql` 和 `21_validate_dws_daily_10k.sql`；
2. 执行 DWS 构建脚本；
3. 执行验收脚本；
4. 检查日期行数、明细对账和行为加总。
