# 简历项目描述

## 推荐项目名称

电商用户行为离线数仓与用户分析平台

## 简历版本（4 条）

- 基于 1 亿级淘宝用户行为日志，在本地三节点 Hadoop 3.1.3/Hive 3.1.3 集群构建 ODS、DWD、DWS、ADS 离线数仓，使用 HDFS 外部表、ORC 和日期分区完成数据接入与分层建模。
- 设计逐层数据质量对账和异常隔离机制，完成 `1000000 = 999429 + 571`、`976621 = 976097 + 524` 等行数校验；使用 `INSERT OVERWRITE` 保证开发任务重复执行不产生重复数据。
- 针对事件随机抽样破坏行为序列的问题，开发确定性用户级哈希抽样脚本，保留 9,660 个用户的完整事件，并构建同用户、同商品、按时间顺序的严格漏斗，得到 691,122 -> 11,101 -> 1,023 的阶段结果。
- 完成 cohort 留存、RFV 用户分层和 39.7 万商品/5,788 类目分析；定位并修复 Hive UTC 导致的日期错分问题，最终制作可交互数据看板展示趋势、留存、漏斗和商品专题。

## 一句话版本

基于 1 亿级电商行为日志搭建 Hadoop/Hive 离线数仓，完成分层建模、质量对账、用户级序列抽样、严格漏斗、留存、RFV 和可视化看板。

## 技术栈

`Python`、`SQL`、`MySQL 5.7`、`Hadoop 3.1.3`、`HDFS`、`YARN`、`MapReduce`、`Hive 3.1.3`、`ORC`、`HTML/CSS/JavaScript`、`VMware/CentOS 7`

## 面试时必须说明的边界

- “1 亿级”指源数据规模，开发 SQL 使用 10K、1M 和约 1% 用户样本分阶段验证；
- 集群为本地三节点虚拟机环境，不宣称是生产集群；
- 数据无金额字段，因此使用 RFV，不声称完成标准 RFM；
- 看板读取 ADS 导出结果，不是实时 BI 系统；
- 项目重点是离线数仓建模、数据质量和指标口径，不是高并发服务。

## 不推荐的夸张写法

- “独立处理 1 亿数据并实时分析”；
- “搭建企业级生产大数据平台”；
- “实现 GMV 和精准推荐系统”；
- “转化率提升 XX%”。

这些说法没有当前项目证据支撑，面试中容易失去可信度。
