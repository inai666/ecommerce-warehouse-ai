# 教程 5：DWD 清洗、日期分区与异常隔离

## 目标

将 ODS 原始数据加工为可分析的 DWD 明细，同时保留所有被拒绝的记录和明确原因。验收时必须满足：

```text
ODS 行数 = DWD 有效行数 + quarantine 异常行数
```

本次预期为 `10000 = 9997 + 3`，对账差额必须为 0。

## 表设计

### `ecommerce_dwd.user_behavior_detail`

- 保留原始五个业务字段；
- 新增上海本地时间文本 `event_time`；
- 按业务日期 `dt` 动态分区；
- 使用 ORC 列式存储，为后续聚合查询减少扫描量。

### `ecommerce_dwd.user_behavior_quarantine`

- 原样保留异常记录；
- 新增 `reject_reason`；
- 当前可区分空业务键、非法行为、空时间、早于范围和晚于范围。

## 有效业务范围

项目数据的主时间范围定义为：

```text
2017-11-25 00:00:00 <= event_time < 2017-12-04 00:00:00
```

对应 Unix 时间戳 `[1511539200, 1512316800)`。左闭右开能避免边界日期重复归属。

## 为什么使用分区

按 `dt` 分区后，查询某一天时 Hive 可以只读取对应目录，而不是扫描整张表。后面的日指标、漏斗和留存分析都会频繁按日期过滤，因此日期是合适的分区字段。

分区不是索引。它实际影响 HDFS 的目录组织，适合低基数且经常作为过滤条件的字段；不要按 `user_id` 这类高基数字段分区。

## 幂等性

开发阶段使用 `INSERT OVERWRITE` 覆盖这份固定样本涉及的日期分区以及异常表结果，因此重复执行不会让记录翻倍。这里不对外部表使用 `TRUNCATE TABLE`，避免不同 Hive 配置下的外部表截断限制。正式处理全量数据时，也会按具体 `dt` 分区覆盖。

## 执行顺序

1. 上传 `10_build_dwd_10k.sql` 和 `11_validate_dwd_10k.sql`；
2. 执行构建脚本；
3. 执行验收脚本；
4. 核对总量、异常原因、日期分区和时间转换结果。

## 核心验收

- ODS：10,000；
- DWD：9,997；
- quarantine：3；
- reconciliation_gap：0；
- 所有 DWD 的 `dt` 位于 `2017-11-25` 至 `2017-12-03`；
- 异常表每行都有非空 `reject_reason`；
- `SHOW PARTITIONS` 能看到每日分区。
