# 项目工程复盘

## 1. 目标与完成范围

项目目标不是简单运行几条 Hive SQL，而是完成一条可解释、可复现、可验收的离线分析链路。目前已完成：

- 数据源校验、全量轻量画像和固定种子抽样；
- MySQL 10K 冒烟与 1M 探索；
- Hadoop/HDFS/YARN/MapReduce 集群验收；
- 10K、1M 事件样本和用户级样本的 ODS/DWD；
- 10K、1M 的 DWS/ADS 日汇总；
- 严格漏斗、留存、RFV、商品与类目专题；
- ADS 数据导出和本地交互看板；
- 时区、异常数据、幂等性和逐层对账。

## 2. 最有价值的工程决策

### ODS 原样保留，DWD 再清洗

原始 Unix 时间戳全部以 BIGINT 保留。异常记录不在 ODS 删除，而是在 DWD 写入 quarantine 并记录原因。这让 `ODS = DWD + quarantine` 可以严格对账。

### 事件样本与用户样本分工

事件随机抽样适合行为比例和日趋势，但会破坏用户序列。首次严格漏斗试算只得到 185 个意向对和 1 个购买对，因此新增用户级哈希抽样：按用户固定抽取约 1%，完整保留入样用户事件。修正后严格漏斗得到 11,101 个意向对和 1,023 个购买对。

### 指标定义先于 SQL

购买用户率、购买事件占比和严格漏斗转化率被明确区分。`buy/cart` 的行为总数比不能替代同一用户商品路径的漏斗。

### 显式时区

Hive/JVM 默认 UTC 导致 `1511539200` 被转换为 `2017-11-24 16:00:00`。修复为：

```sql
from_utc_timestamp(event_ts * 1000, 'Asia/Shanghai')
```

随后重建 10K、1M 和用户级 DWD 及其下游，统一验收日期均为 `2017-11-25` 至 `2017-12-03`，越界日期记录为 0。

## 3. 数据质量与幂等性

- 10K：`10000 = 9997 + 3`；
- 1M：`1000000 = 999429 + 571`；
- 用户级：`976621 = 976097 + 524`；
- 使用外部表和独立 HDFS 目录隔离三套样本；
- 使用 `INSERT OVERWRITE` 重建分区和 ADS 输出，重复执行不累加；
- 10K 作为回归基线，1M 扩容后仍保持 10K 表总量不变。

## 4. 性能观察

| 任务 | 实际耗时 |
|---|---:|
| 1M DWS 多个 COUNT DISTINCT | 67.885 秒 |
| 1M ADS 9 行输入端到端写入 | 39.448 秒 |
| 用户级 DWD 构建 | 27.278 秒（时区修复后） |
| 严格漏斗构建 | 29.811 秒（时区修复后） |
| 留存构建 | 56.761 秒 |
| RFV 构建 | 51.309 秒 |
| 商品与类目构建 | 72.225 秒 |

1M 原始 CSV 逻辑大小为 35.0 MB，DWD ORC 为 14.2 MB，减少约 59.4%。由于 DWD 新增了时间字段，这不是严格同字段压缩实验，只作为工程观察。

主要性能判断：

- `COUNT(DISTINCT)` 带来明显 shuffle 成本；
- 即便 ADS 输入只有 9 行，Hive/YARN 启动和写 ORC 仍有较高固定开销；
- 当前节点每台资源有限，性能数字只适用于本地三节点环境；
- 下一步若优化，可考虑 Tez/Spark 引擎、合理 reducer、列裁剪、分区过滤和小文件治理。

## 5. 遇到的问题

| 问题 | 根因 | 处理 |
|---|---|---|
| MySQL Error 2068 | LOCAL INFILE 被客户端禁用 | Workbench 连接设置 `OPT_LOCAL_INFILE=1` |
| MySQL Error 2013 | 查询超过 30 秒 | read timeout 调至 300 秒，并增加 `(behavior,user_id)` 索引 |
| Hive `WITH` 解析失败 | Hive 3.1.3 对 INSERT 后 CTE 兼容有限 | 改为嵌套子查询 |
| `rows` 别名解析失败 | Hive 保留关键字 | 改名为 `row_count` |
| TSV 混入日志 | 多个 SLF4J binding 将 INFO 写入 stdout | 按固定字段数过滤并检查表头/行数 |
| 日期出现 2017-11-24 | Hive 默认 UTC | 显式上海时区并全链路回归 |
