# 面试答辩手册

## 30 秒介绍

这是一个基于淘宝用户行为日志的离线数仓项目。源数据超过 1 亿行，我先用 Python 流式画像并生成固定样本，在三节点 Hadoop/Hive 集群中构建 ODS、DWD、DWS、ADS。项目重点是数据质量和指标口径：异常时间进入隔离表，所有层级严格对账；另外发现事件抽样破坏用户序列后，重新设计用户级抽样，用于严格漏斗、留存和 RFV。最后把 ADS 导出为交互看板。

## 高频问题

### 为什么 ODS 不直接清洗？

ODS 要保留源数据，便于追溯。异常时间仍是可解析整数，只是业务范围非法，因此在 DWD 隔离并记录原因。这样可以验证 `ODS = DWD + quarantine`。

### 为什么要三种样本？

10K 用于冒烟；1M 事件样本用于指标开发和分布观察；用户级样本用于需要完整行为序列的漏斗、留存和 RFV。事件抽样不能回答序列问题。

### 严格漏斗和行为数相除有什么区别？

严格漏斗要求同一用户、同一商品，并且 `pv -> fav/cart -> buy` 的时间顺序成立。行为数相除可能来自不同用户和商品，只是数量比。

### 如何保证幂等？

开发脚本使用 `INSERT OVERWRITE` 覆盖固定分区或整张结果表；不同样本使用独立表和 HDFS 目录；重跑后通过行数、行为分布和回归表校验。

### 为什么使用 ORC？

ORC 适合 Hive 列式分析，支持列裁剪和统计信息。在本项目中 1M CSV 逻辑大小约 35.0 MB，DWD ORC 约 14.2 MB。体积减少是观察结果，不能单独证明所有查询都更快。

### 时区问题是怎么发现的？

留存结果出现业务范围外的 `2017-11-24` cohort。进一步验证发现 `from_unixtime(1511539200)` 得到 UTC 的 16:00，而上海时间应为次日 00:00。修复后重建三套 DWD 及下游，统一检查最小/最大日期和越界行数。

### 为什么 D7 会高于 D1？

这里是经典的“第 N 天是否活跃”口径，不要求连续活跃。用户可能第 1 天没回来，第 7 天回来，因此 D7 可以高于 D1。较晚 cohort 还存在右删失，不能将缺少观察窗口解释为零留存。

### RFV 的 V 是什么？

原数据没有金额，所以 V 不是 Monetary，而是透明的行为价值代理：pv=1、fav=2、cart=3、buy=5。分数和分群阈值都保留在 SQL 中，可调整和复算。

### 项目最大不足是什么？

没有生产调度、实时链路、权限血缘和全量专题结果；集群资源较小。当前价值在于完整的离线分层、质量对账、序列抽样和口径治理。下一步可增加 Airflow、Spark/Tez、ClickHouse/API 和自动化测试。

## 可现场演示的顺序

1. README 的架构与核心数字；
2. 看板经营概览；
3. 严格漏斗和事件抽样失败案例；
4. 留存矩阵与右删失说明；
5. RFV 分群；
6. 时区修复和 `ODS=DWD+异常` 对账 SQL；
7. 性能复盘和下一步优化。

## 自检问题

- 能否解释每一层表的粒度？
- 能否区分购买事件、购买用户和严格转化率？
- 能否解释为什么不能计算 GMV 和标准 RFM？
- 能否解释样本选择对问题类型的影响？
- 能否说明一次实际故障的现象、根因、修复和回归？
- 能否承认本地集群与生产系统的差距？

这六项能清楚回答，项目在实习面试中就具备可信度。
